# BingX CRM V0.9 — Telegram

Telegram-бот для партнёрской программы BingX. Веб-интерфейса нет.

## Термины в интерфейсе

- **Баланс сейчас** — значение `balanceVolume`, которое BingX отдаёт как текущие чистые активы пользователя. Это не обязательно равно свободной сумме, доступной к выводу прямо сейчас.
- **Пополнения** — реальные операции ввода средств на BingX за выбранный период.

## Возможности

- Главная сводка — всегда за **90 дней**.
- Раздел **📊 Трейдеры**: общий рейтинг всех рефералов, период **30 / 60 / 90 дней**. В каждой строке видны дата регистрации и последнее подтверждённое пополнение из доступной 90-дневной истории BingX.
- Фильтры: **Все / Активные / Неактивные / Прямые / Непрямые**.
- Сортировка: **Объём / Комиссия / Баланс / Пополнения**.
- Неактивный = **более 3 завершённых дней без торговли**.
- Алерт на пополнение **USDT больше порога** (по умолчанию 500, меняется в `.env`).
- Выгрузка CSV за 30 / 60 / 90 дней.
- Несколько Telegram ID: каждый разрешённый ID получает алерты и ежедневный отчёт.
- Повторные попытки при сбоях Telegram и плановой синхронизации.

## Обновление до V0.9

Подробности изменений — в `UPDATE_V0.9.md`.

1. Останови бота (`pm2 stop bingx_crm` или закрой окно `start.bat`).
2. **Сохрани свои `.env` и `data/bingx_crm.sqlite3`.** В этом архиве ключей и базы нет.
3. Замени файлы проекта файлами из V0.9 и верни на место свои `.env` и `data/`.
4. Зависимости не менялись; при необходимости: `python -m pip install -r requirements.txt`.
5. Запусти обратно (`pm2 restart bingx_crm` или `start.bat`) и проверь лог (`pm2 logs bingx_crm --lines 80`).

Для V0.9 миграция базы не требуется: схема не менялась. Пользователи, история торгов и пополнений сохраняются. Старые пополнения повторно **не рассылаются**.


## Дата регистрации и последнее пополнение

- **Регистрация** — дата `registerDateTime` из списка рефералов BingX.
- **Последнее пополнение (90д)** — самая свежая подтверждённая операция пополнения из доступной истории BingX. Показываются сумма, валюта и дата; в карточке UID также время.
- Это поле не зависит от выбранного периода рейтинга 30/60/90 дней: API истории пополнений у нас всё равно хранится в окне до 90 дней.
- Если BingX не подтвердил историю по UID, бот пишет **«данные недоступны»**, а не показывает ложный ноль.

## Telegram ID

Можно указывать несколько ID через запятую, пробел, `;` или перенос строки:

```env
ALLOWED_TELEGRAM_IDS=123456789,987654321;555666777
ADMIN_TELEGRAM_ID=123456789
```

Все они имеют доступ к боту, получают алерты неактивности и пополнений и отчёт в 08:00 МСК. `ADMIN_TELEGRAM_ID` один и должен входить в список разрешённых; только он видит ручную синхронизацию.

## Алерт пополнения

- Порог строгий: при `DEPOSIT_ALERT_THRESHOLD_USDT=500` алерт приходит на **501 USDT**, но не на 500 USDT.
- Порог применяется только к **USDT**: Agent API отдаёт количество монеты, а не её стоимость в долларах. BTC/ETH по выдуманному курсу не пересчитываются.
- Алерт приходит на **любое впервые увиденное пополнение**, включая самое первое пополнение нового реферала и пополнения после временного сбоя API по этому UID.
- Пополнения, сделанные до установки/обновления бота, не рассылаются. Пополнения старше 7 дней, которые всплыли с опозданием (например, после долгого сбоя API), сохраняются в статистике, но без алерта.

Пример:

```text
🟢 ПОПОЛНЕНИЕ

UID: 12345678
Сумма: +2 000 USDT
Время: 07.10.2026 12:10 МСК

Баланс: 12 450 USDT
Объём 30д: 14.13M USDT
Статус: 🟢 Активен
```

## Выводы средств

Алерт о выводах пока **не реализован**, и это не ограничение бота, а BingX:

- в официальном Agent API (документация по состоянию на 19.09.2026) нет метода для выводов рефералов;
- проверка `diagnose_withdrawals.py` на реальном ключе: `depositDetailList` с `bizType=2` → `bizType-illegal`, остальные варианты → `api is not exist`;
- выводы рефералов видны только в веб-кабинете Partner Hub («Deposit & Withdrawal Management»).

Запрос на read-only метод отправлен в BingX. Как только метод появится, алерт на выводы с любой суммы подключается по той же схеме, что и пополнения. Уменьшение `balanceVolume` выводом не считается: баланс падает и от убыточной торговли.

`/openApi/api/v3/capital/withdraw/history` не используется: это выводы владельца API-ключа, а не рефералов.

## Расписание

- 07:15 МСК — синхронизация.
- 08:00 МСК — ежедневный отчёт.
- 14:00 МСК — синхронизация.
- 20:00 МСК — синхронизация.
- Если плановая синхронизация падает — повторы через 5 и 15 минут.
- Если бот был выключен, при следующей синхронизации он сам догружает пропущенные дни торговли (до 90 дней).
